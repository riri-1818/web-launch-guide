1STAGE 01 · 1〜3日

契約直後の準備

ここで止まると全部が遅れます。特に「ドメイン管理会社にログインできるか」は、最初の週に必ず確かめます。

お客様がやること

Cloudflareアカウントの作り方

  1. dash.cloudflare.com/sign-up を開く
  2. お店の共有メールアドレスとパスワードを入れて登録（個人のアドレスより、担当が変わっても困らないアドレスがおすすめ）
  3. 届いた確認メールのボタンを押す
  4. 右上の人のマーク → Profile → Authentication で、2段階認証（スマホの認証アプリ）をオンにする
  5. 左のメニューの Manage Account → Members → Invite で、制作側のメールアドレスを招待する（権限は Administrator）
なぜお客様のアカウント？サイトもドメインの設定もお客様の名義になります。制作側との契約が終わっても、招待を外すだけでそのまま使い続けられます。

制作側がやること

dig example.com.au NS +short
dig example.com.au A +short
dig www.example.com.au CNAME +short
dig example.com.au MX +short
dig example.com.au TXT +short
dig _dmarc.example.com.au TXT +short
dig google._domainkey.example.com.au TXT +short
dig selector1._domainkey.example.com.au CNAME +short

結果はそのままテキストで保存。できれば管理会社のDNS画面のスクショももらう（dig では拾えないレコードがあるため）。

3STAGE 03 · 30分

サイトをCloudflareに載せる

お客様の作業はありません。制作側が、お客様のCloudflareアカウントの中にサイトを置きます。

制作側がやること

A. GitHubとつなぐ方法（おすすめ。push すると自動で更新される）

  1. dash.cloudflare.com にログインし、左上のアカウント名でお客様のアカウントに切り替える（自分のアカウントに作らないよう注意）
  2. 左メニューの Workers & Pages を開く（Compute の中にあることもある）
  3. Create → Pages タブ → Connect to Git
  4. GitHub を選び、このサイトのリポジトリだけを許可する（Only select repositories）
  5. 設定を入れる
    • Project name：お店の名前を英小文字で（例：shop-name）。これが「〇〇.pages.dev」になる
    • Production branch：main
    • Framework preset：None（手書きのHTMLの場合）
    • Build command：空欄
    • Build output directory：HTMLが入っているフォルダ（リポジトリ直下なら /、public に入れていれば public）
  6. Save and Deploy → 1分ほどで https://〇〇.pages.dev が開けるようになる

B. 手元から直接上げる方法（GitHubをお客様のアカウントとつなぎたくないとき）

npx wrangler login
npx wrangler pages deploy ./public --project-name=shop-name

ログイン時にお客様のアカウントを選ぶ。Bで作ったプロジェクトは、後からA（GitHub連携）に切り替えられないので、最初にどちらか決める。

確認用URLを検索に出さない設定

HTMLと同じフォルダに _headers というファイルを置く。pages.dev の方だけ検索に出なくなり、本番のドメインには影響しないので、公開時に外し忘れる心配がありません。

https://:project.pages.dev/*
  X-Robots-Tag: noindex
補足：Cloudflare は新しい作りの Workers（静的アセット）も勧めていますが、お店のサイトなら Pages で十分です。問い合わせフォームや投稿機能（Workers・D1 を使う部品）を付ける場合も、同じアカウントの中に置きます。
4STAGE 04 · 作業30分＋待ち数時間〜48時間

ドメインをCloudflareに引っ越す

ドメインは今の管理会社に残したままで、「案内表（DNS）」の置き場だけをCloudflareに移します。中身をそっくり写してから移すので、この段階では今のサイトもメールもそのまま動き続けます。公開日の3〜7日前に済ませておくと、公開日はつなぎ替えるだけになります。

制作側がやること（前半）

  1. お客様のCloudflareアカウントで、Account home の Add a domain（または Add a site）を押す
  2. ドメイン名を www なしで入れる（例：example.com.au）。Quick scan for DNS records を選んで Continue
  3. プランは Free を選ぶ
  4. 取り込まれたDNSレコードを、段階1で記録したものと1行ずつ突き合わせる。足りないものは Add record で足す
確かめるもの何のため注意
MX（全部）メールを受け取る優先度（Priority）の数字も同じに
TXT：v=spf1 で始まるものメールが迷惑メール扱いされないため1つのドメインに1行だけ
TXT：_dmarc同上なければ無理に足さなくてよい
TXT または CNAME：〇〇._domainkey（DKIM）同上Google は google._domainkey、Microsoft は selector1/selector2
CNAME：autodiscoverOutlook の自動設定Microsoft 365 の場合
TXT：google-site-verification などGoogle や Meta の持ち主確認消すと後で確認し直しになる
A・CNAME（@ と www）今のサイト公開日までそのまま。段階5で置き換える
  1. メール関係のレコード（MX の行き先、mail.〇〇、autodiscover など）は、Proxy status をグレーの雲（DNS only）にする
  2. Continue を押すと、Cloudflare のネームサーバーが2つ表示される（例：ada.ns.cloudflare.com と bob.ns.cloudflare.com。名前は毎回違う）。メモしてお客様に送る
  3. 管理会社で DNSSEC がオンになっていないか確かめる（dig example.com.au DS +short で何か出たらオン）。オンなら、次の作業の前にオフにしてもらう
ここを間違えると止まるオレンジの雲のままだとメールが届かなくなります。DNSSEC がオンのままネームサーバーを変えると、サイトもメールもつながらなくなります。

お客様がやること

15分・画面共有で一緒にやるのがおすすめ
  1. ドメイン管理会社にログインする
  2. 該当のドメインを開き、「ネームサーバー」（Nameservers、DNS servers と書かれていることも）を探す
  3. 「自分で指定する」（Custom、Use my own nameservers など）を選ぶ
  4. 今入っているネームサーバーをすべて消し、制作側から届いた2つを入れる（3つ目以降は入れない）
  5. 保存する。確認メールやSMSが届いたら承認する

画面の名前は会社ごとに違います。見つからなければ、管理会社のヘルプで「change nameservers」と検索するか、そのまま制作側に画面を見せてください。

制作側がやること（後半）

5STAGE 05 · 公開日 · 30分

独自ドメインをサイトにつなぐ

公開日にやるのはこの段階です。旧サイトから新サイトへの切り替えは数分で済みます。お客様の作業はありません。

制作側がやること

切り替えの前に

/about-us        /about/     301
/services.html   /services/  301
/contact-us      /contact/   301
/blog/*          /news/      301

切り替え

  1. Cloudflare の DNS → Records で、旧サイト向けの @ と www の A・CNAME を削除する（メールのレコードは絶対に消さない）。削除した内容はメモしておく（戻すとき用）
  2. Workers & Pages → このプロジェクト → Custom domains → Set up a custom domain
  3. example.com.au を入れて Continue → Activate domain（同じアカウント内なのでDNSは自動で作られる）
  4. 同じように www.example.com.au も追加する
  5. 両方の Status が Active になるまで待つ（ふつう数分。https の鍵＝SSL証明書も自動で発行される）

仕上げ

  1. www ありを www なしにまとめる：ドメインの Rules → Redirect Rules → テンプレート「Redirect from WWW to root」を使う（301、クエリ文字列を残す）
  2. SSL/TLS → Edge Certificates で Always Use HTTPS をオン
  3. どちらを本物にするか（www あり／なし）は、旧サイトと同じにするのが安全。旧サイトが www ありなら、手順6は逆向きにする
うまくいかなかったときの戻し方Custom domains から両方を外し、手順1でメモした旧サイトのレコードを戻す。数分で旧サイトに戻ります。

?TROUBLESHOOTING

困ったとき・よくある質問

ドメイン管理会社にログインできない

ログイン画面の「パスワードを忘れた」から再設定。メールも分からなければ、管理会社のサポートに本人確認を依頼します（.au は登録したABNや会社名で確認されることが多い）。

ドメインが前の制作会社の名義になっている

名義をお客様に移してもらうよう依頼します。数日〜数週間かかるので、契約直後に始めます。

ネームサーバーを変えたのに48時間たっても Active にならない

入力ミス（綴り違い・3つ目が残っている）と、DNSSEC がオンのままでないかを確かめます。

メールが届かなくなった

MX が段階1の記録どおりか、メール用の行がオレンジの雲になっていないかを確かめます。

送ったメールが相手の迷惑メールに入る

SPF と DKIM の行が残っているか、SPF が2行になっていないかを確かめます。

新しいサイトが自分のスマホだけ出ない

古い情報が残っているだけのことが多いです。携帯回線に切り替えるか、数時間待ちます。

「この接続は安全ではありません」と出る

Custom domains の Status が Active か確かめます。証明書の発行中なら数分〜数時間待ちます。

Cloudflare の画面がこの手順書と違う

Cloudflare は画面の名前がよく変わります。この手順書は2026年10月時点です。上の検索バーで英語の名前（Custom domains など）を入れると早く見つかります。

費用はいくらかかる？

Cloudflare の無料プランと Pages の無料枠で、お店のサイトなら月額0円で動きます。かかるのは、今までどおりのドメイン代（管理会社へ年に一度）と、メールのサービス代（Google Workspace などを使っている場合）だけです。

ドメインごとCloudflareに移した方がいい？

必要ありません。管理会社はそのままで、案内表だけ移すのがいちばん安全です（.com.au は移せる会社が限られるため）。

新しいドメインを取る場合は？

段階1でお客様名義で購入してもらいます。その場合は段階4の「突き合わせ」が不要で、ネームサーバーを変えるだけです。
