2回目で公開できる条件
  • お客様がドメインの管理画面にログインできる
  • 修正の締め切り（2回目の3日前）までに「これでOK」が出ている
  • 今のメールの種類が分かっている
  • 2回目を午前〜昼すぎに入れている（待ち時間を面談中に吸収するため）
3回目が必要になるとき
  • ドメインが前の業者の名義で、ログインが取れていない
  • 修正が締め切りに間に合わない、ページの追加など大きな変更が出た
  • メールが古いサーバーに付いていて、メールの引っ越しが先に要る

Cloudflareアカウントの作り方（5分）

  1. dash.cloudflare.com/sign-up を開く
  2. お店の共有メールアドレスとパスワードを入れて登録（担当が変わっても困らないアドレスがおすすめ）
  3. 届いた確認メールのボタンを押す
  4. 右上の人のマーク → Profile → Authentication で、2段階認証（スマホの認証アプリ）をオンにする
  5. 左のメニューの Manage Account → Members → Invite で、制作側のメールアドレスを招待する（権限は Administrator）
なぜお客様のアカウント？サイトもドメインの設定もお客様の名義になります。制作側との契約が終わっても、招待を外すだけでそのまま使い続けられます。

B. お客様のCloudflareにサイトを置く

  1. dash.cloudflare.com で、左上のアカウント名からお客様のアカウントに切り替える（自分のアカウントに作らない）
  2. Workers & Pages（Compute の中にあることも）→ Create → Pages タブ → Connect to Git
  3. GitHub のこのサイトのリポジトリだけを許可する（Only select repositories）
  4. 設定：Project name＝お店の名前を英小文字で（例：shop-name）／Production branch＝main／Framework preset＝None／Build command＝空欄／Build output directory＝HTMLのフォルダ
  5. Save and Deploy → https://shop-name.pages.dev が開ける

GitHub をお客様のアカウントとつなぎたくない場合は、手元から直接上げる（後からGitHub連携には切り替えられない）。

npx wrangler login
npx wrangler pages deploy ./public --project-name=shop-name

確認用URLを検索に出さないよう、HTMLと同じフォルダに _headers を置く。本番ドメインには効かないので外し忘れの心配なし。

https://:project.pages.dev/*
  X-Robots-Tag: noindex

C. ドメインをCloudflareに登録（ネームサーバーを変える手前まで）

  1. お客様のアカウントで Account home → Add a domain（または Add a site）
  2. ドメイン名を www なしで入れる → Quick scan for DNS records → Continue → プランは Free
  3. 取り込まれたDNSレコードを、1回目の前に記録したものと1行ずつ突き合わせる。足りないものは Add record で足す
確かめるもの何のため注意
MX（全部）メールを受け取る優先度（Priority）の数字も同じに
TXT：v=spf1 で始まるもの迷惑メール扱いされないため1つのドメインに1行だけ
TXT：_dmarc同上なければ無理に足さなくてよい
〇〇._domainkey（DKIM）同上Google は google._domainkey、Microsoft は selector1/selector2
CNAME：autodiscoverOutlook の自動設定Microsoft 365 の場合
TXT：google-site-verification などGoogle や Meta の持ち主確認消すと確認し直しになる
A・CNAME（@ と www）今のサイト公開の瞬間まで残す
  1. メール関係の行（MX の行き先、mail.〇〇、autodiscover など）は Proxy status をグレーの雲（DNS only）にする
  2. 表示された Cloudflare のネームサーバー2つ（例：ada.ns.cloudflare.com／bob.ns.cloudflare.com、名前は毎回違う）をメモする。ここで止めておく
  3. 1回目の前に打った dig … DS で何か出ていたら DNSSEC がオン。2回目までにお客様と一緒にオフにしておく（オンのまま書き換えるとサイトもメールもつながらなくなる）

D. 2回目の前日チェック

ここで1つでも×なら2回目は「公開日」ではなく「仕上げの確認」に切り替え、3回目を公開日にします。前日までにお客様に一言伝えます。
3STEP 03 · 2回目の面談 · 90〜120分

2回目の面談＝公開日

最初にネームサーバーを書き換え、Cloudflare に切り替わるのを待つあいだに、最終確認と説明を済ませます。ふつうは数分〜1時間ほどで切り替わるので、多くの場合は面談中に公開まで終わります。

  1. 0〜15分ネームサーバーを書き換えるお客様のスマホ・パソコンで、制作側と一緒に
  2. 15〜60分待つあいだに最終確認・更新のしかたの説明・引き継ぎメモ・請求書・権利の確認
  3. Active 後切り替え制作側の作業10〜30分。お客様は休憩でOK
  4. 最後の15分一緒にチェックお客様のスマホで開く・メールを送り合う

お客様がやること

最初の15分
  1. ドメイン管理会社にログインする
  2. 該当のドメインを開き、「ネームサーバー」（Nameservers、DNS servers と書かれていることも）を探す
  3. 「自分で指定する」（Custom、Use my own nameservers など）を選ぶ
  4. 今入っているネームサーバーをすべて消し、制作側が見せる2つを入れる（3つ目以降は入れない）
  5. 保存する。確認コードやメールが届いたら承認する

画面の名前は会社ごとに違います。制作側が横で一緒に探します。

制作側がやること

待つあいだ

Active になったら切り替え

  1. Cloudflare の DNS → Records で、旧サイト向けの @ と www の A・CNAME を削除する（メールの行は絶対に消さない）。消した内容はメモ（戻すとき用）
  2. Workers & Pages → このプロジェクト → Custom domains → Set up a custom domain → example.com.au → Activate domain
  3. 同じように www.example.com.au も追加する
  4. 両方の Status が Active になるまで待つ（ふつう数分。https の証明書も自動で発行される）
  5. Rules → Redirect Rules → テンプレート「Redirect from WWW to root」（旧サイトが www ありなら逆向き）
  6. SSL/TLS → Edge Certificates → Always Use HTTPS をオン

その場でチェック

うまくいかなかったときの戻し方Custom domains から両方を外し、消した旧サイトのレコードを戻す。数分で旧サイトに戻ります。メールの行は触っていないので、メールは止まりません。

困ったとき・よくある質問

ドメイン管理会社にログインできない

ログイン画面の「パスワードを忘れた」から再設定。メールも分からなければ、管理会社のサポートに本人確認を依頼します（.au は登録したABNや会社名で確認されることが多い）。2回目までに解決しなければ、公開は3回目にします。

ドメインが前の制作会社の名義になっている

名義をお客様に移してもらうよう依頼します。数日〜数週間かかるので、1回目の面談の直後に始めます。

ネームサーバーを変えたのに48時間たっても Active にならない

入力ミス（綴り違い・3つ目が残っている）と、DNSSEC がオンのままでないかを確かめます。

メールが届かなくなった

MX が記録どおりか、メール用の行がオレンジの雲になっていないかを確かめます。

送ったメールが相手の迷惑メールに入る

SPF と DKIM の行が残っているか、SPF が2行になっていないかを確かめます。

新しいサイトが自分のスマホだけ出ない

古い情報が残っているだけのことが多いです。携帯回線に切り替えるか、数時間待ちます。

「この接続は安全ではありません」と出る

Custom domains の Status が Active か確かめます。証明書の発行中なら数分〜数時間待ちます。

Cloudflare の画面がこの手順書と違う

Cloudflare は画面の名前がよく変わります。この手順書は2026年10月時点です。上の検索バーで英語の名前（Custom domains など）を入れると早く見つかります。

毎月の費用はいくらかかる？

Cloudflare の無料プランと Pages の無料枠で、お店のサイトなら月額0円で動きます。かかるのは、今までどおりのドメイン代（管理会社へ年に一度）と、メールのサービス代（Google Workspace などを使っている場合）だけです。

ドメインごとCloudflareに移した方がいい？

必要ありません。管理会社はそのままで、案内表だけ移すのがいちばん安全です（.com.au は移せる会社が限られるため）。

新しいドメインを取る場合は？

1回目の面談のあとにお客様名義で購入してもらいます。DNSの突き合わせが不要になるので、2回目で公開しやすくなります。
